1. First create/invite their user in Supabase → Authentication → Users.
2. In ONLYUSLABS Admin → Administrators, add the exact same email address.
3. Select Admin or Editor. Admins can manage CRM, content and settings. Editors can manage content and media only.
4. The user can sign in only when both the Supabase Auth account and active admin allow-list row exist.

IMPORTANT SECURITY / PRIVACY NOTES
- Do not paste or deploy the Supabase secret/service_role key in frontend code.
- The SQL enables Row Level Security. Do not disable RLS to make an error disappear.
- Public visitors can submit new enquiries only; they cannot read CRM records.
- Do not store patient records, medical histories, passwords, payment details or other sensitive data in this website CRM. This is a general business enquiry CRM, not a healthcare records system.
- The media bucket is public-read so published website images can load. Upload, update and delete are restricted to active administrators.
- Enable MFA for the owner in Supabase Authentication settings.
- Set up a backup policy for the Supabase database before production use.

TROUBLESHOOTING
- “Database setup has not been completed”: run the full SQL script in the correct Supabase project and reload /admin/.
- “This account is not authorised”: check the email exists in Supabase Auth and is active in the admin_users table / Admins screen.
- Login loops: verify Supabase Site URL and Redirect URLs, including the exact Netlify URL and custom domain.
- Contact form errors: confirm the SQL script ran and the leads table has RLS policies; never disable RLS.
- Media upload errors: confirm the onlyuslabs-media bucket and storage policies were created by the SQL script.
